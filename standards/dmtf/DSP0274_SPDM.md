# DMTF DSP0274 — SPDM機器認証・測定・鍵交換

[公式原典 v1.4.0](https://www.dmtf.org/sites/default/files/standards/documents/DSP0274_1.4.0.pdf) と [公開版一覧](https://www.dmtf.org/dsp/DSP0274)。これを基準版とし、実装は選択した版と能力を調べる。対象例はLinux端末内の周辺機器で、NICなどのコンポーネントにSPDM Responderが存在する拡張構成を想定する。

## 1. 通信の層とフォーマット

SPDMメッセージはバージョン、RequestResponseCode、Param1、Param2の各1オクテットで始まり、コードにより残りの内容が変わる。下位輸送とセキュアセッションのカプセル化は関連仕様で定義される。

| 交換 | フォーマットの要点 | 確認する意味 |
|---|---|---|
| GET_VERSION / VERSION | 対応バージョンの一覧 | 共通版を選び、ラボの最低許容版を確認 |
| GET_CAPABILITIES / CAPABILITIES | 能力フラグ、対応する版では転送サイズ情報等 | 証明書、Challenge、測定、セッション等の使える組合せを確認 |
| NEGOTIATE_ALGORITHMS / ALGORITHMS | ハッシュ、署名、鍵交換やAEAD等の候補と選択 | 版と能力に照らしてポリシーを適用 |
| GET_DIGESTS / DIGESTS | スロットの対応情報と証明書チェーンのダイジェスト | 期待したスロットと証明書チェーンを関連付け |
| GET_CERTIFICATE / CERTIFICATE | スロットと範囲、分割応答 | 応答範囲と長さに上限を設け、組み立ててチェーンを検証 |
| CHALLENGE / CHALLENGE_AUTH | nonce、署名などを含む認証交換 | 証明書鍵の保有と交換内容を確認 |
| GET_MEASUREMENTS / MEASUREMENTS | 測定レコード、要求時の署名関連データ | 署名付き取得を選び、対象・鮮度・値を評価 |

測定レコードのブロックにはIndex、Measurement Specification、サイズ、測定値のデータがある。ブロック番号だけでNICファームウェアの意味を一般化せず、測定仕様と機器プロファイルを照合する。

## 2. 正常シーケンスと鍵管理

1. RequesterとResponderが共通版、機能、アルゴリズムを選ぶ。
2. 証明書を使うプロファイルでチェーンを取得し、信頼アンカーと機器に要求したIDへ照合する。
3. Challenge等で証明書鍵の保有を検証する。署名付き測定を要求し、対応するトランスクリプトの署名、nonce、測定データと参考値を検査する。
4. アプリケーションデータを保護する場合は、選択した方式の鍵交換とセッションを確立して [DSP0277](DSP0277_Secured_Messages.md) を使う。

長期証明書鍵、セッション固有鍵、上位で集約結果を署名する鍵を分離する。Challenge成功だけで測定合格と判断しない。端末内のRequesterが出したPASSを外部Verifierに渡す設計では、Requesterの信頼根拠、結果と対象機器の結合、鮮度、使用した期待値を定義する。

## 3. OSS・設定・証跡

[DMTF libspdm](https://github.com/DMTF/libspdm) はRequester／Responderのプロトコル部品。[spdm-emu](https://github.com/DMTF/spdm-emu) は採用版でサポートされるバインディングを使った演習候補。実験ではSPDM版、スロット、信頼アンカー、測定署名要求、輸送アダプター、測定インデックスの意味を固定する。測定内容や接続先を記録し、鍵そのものは運用ログに出さない。

| 条件 | 合格判定 |
|---|---|
| 正規チェーン・署名・測定値 | それぞれの判定と、適用プロファイルを記録 |
| 対応版または署名方式なし | 機能が合わない理由で中断 |
| 不明な証明書スロット／別機器のチェーン | 対象への結合または信頼アンカーで拒否 |
| 正しい証明書だが測定値が承認外 | コンポーネント評価を不合格にする |
| 署名付き測定必須の試験で署名なし | 評価不能として隔離。バックエンドのRADIUS成功と分離 |

## 4. 設計演習

AのTPMとAに装着したNICを別コンポーネントとし、それぞれの期待値発行元を決める。NIC交換時の証明書更新と許可条件、Requesterが停止して欠測したときの処理、集約結果を再接続時に再利用しない方法を設計する。基本ラボではSPDMを無効にでき、SPDM必須を選んだ拡張ポリシーでのみコンポーネント欠落を失敗とする。
