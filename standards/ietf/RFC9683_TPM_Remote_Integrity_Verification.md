# RFC 9683 — TPMを備えた機器のリモート完全性検証

[公式原典](https://www.rfc-editor.org/rfc/rfc9683.html)（Informational）。ネットワーク機器のRIVワークフローをLinux端末へ応用する。TPM内の構造体は [TCG TPM Library](../tcg/TPM2_Library.md)、YANGでのネットワーク取得は [RFC 9684](RFC9684_CHARRA.md)。

## 1. 何を検証できるか

PCRは測定の順序と履歴を集約する。イベントログは「何を・どのバンク・どのPCRに反映したか」の解釈に必要。VerifierはQuoteが固定したPCRの組合せにログが整合するかを確認し、さらに各測定値が承認済み参考値に合うかを判断する。ログがPCRに整合しても、測定対象が許可されるとは限らない。評価対象のファームウェア、ブートチェーン、設定、実行時計測のカバレッジを先に決める。

## 2. フォーマットと鍵

| 値 | 形式・出所 | 検証方法 |
|---|---|---|
| チャレンジ | Verifierが生成する予測困難なバイト列 | 登録IDと要求に結び付け、有効期限と使用済みを確認 |
| Quote | TPMの署名対象アテステーション構造体と署名 | AK、構造体型、nonce、PCR selection、PCR digest |
| ログ | プラットフォームの測定プロファイルで構造化 | 対象PCRへのExtendを先頭または信頼済みチェックポイントから再現 |
| 参考値 | 承認済みファームウェア／構成のダイジェスト・メタデータ | 発行者の信頼、対象プラットフォームとバージョン |
| 認可結果 | ポリシー固有のサービス間オブジェクト | Verifierの真正性と現在の接続の対応を照会 |

AKはQuote署名、EKは登録時にTPM由来を評価するための鍵。証明書・Endorsementの発行元を登録時のプロファイルで固定し、旧AKの失効、TPM交換、発行CA更新の承認を記録する。管理経路のTLS鍵は独立に管理する。RFC 9683は単独のネットワーク・ワイヤ形式を定義しない。

## 3. 一連の処理

1. 承認済み構成からReference Valuesを配布し、端末とAKを登録する。
2. 起動後、Verifierが測定ポリシーで選んだPCRとnonceを要求する。
3. 受信したQuoteを認証し、ログを再計算してQuoteのPCR digestに結び付ける。
4. 各測定値とイベントの意味を承認済み参考値・機種・バージョンで評価する。
5. PASS、FAIL、判断材料不足を区別して返す。スイッチ認可側が結果とセッションを照合する。

PCR読み出しとQuoteの間にExtendが入ると、両者の結果がずれることがある。計測範囲が可変な場合はQuoteと整合するログ接頭辞を特定するか、新nonceで取り直す。結果を一致させるためにログ検証をスキップしない。

## 4. 実装・設定の例

- QEMU／OVMF／swtpmの組合せでブートログを取り、`tpm2_eventlog` と `tpm2_checkquote` の結果を比較する。コマンドで署名が通ることと、端末の測定ポリシー適合を別々に記録する。
- Keylimeでは measured boot policy と runtime policy の測定対象を分け、版付きで保管する。許可リストを本番相当の端末から無条件に採取する運用を避け、承認済みイメージに紐付ける。
- ［設定例］対象は端末ごとにバンクを明示し、新旧2つの承認済みブート構成を短期間だけ認める。切替期間終了後に旧版の認可を失効させる。

## 5. 正常／異常試験と演習

| 変更点 | 期待する結果 | 証跡 |
|---|---|---|
| 承認済みイメージを通常起動 | Quote・ログ・参考値に整合 | 要求ID、PCR selection、評価ポリシー版 |
| 旧Quoteを新規要求への応答として評価 | nonce不一致で失敗 | Verifierの拒否理由 |
| ログイベントを欠落させる | 該当PCRの再計算で不一致 | バンク・PCR・イベント位置 |
| 承認済み範囲外の構成を測定 | Quoteとログが整合してもポリシー失敗 | 差分のイベント種別・該当参考値 |
| 予定外のTPM置換 | 登録済みAKで認証できず隔離 | 端末IDと鍵登録履歴 |

演習では「有効な署名・Quoteとログの整合・ポリシー合格」を横軸にした判定表を作り、各段階で失敗理由を出す。ファームウェア更新の受入試験では旧版が失効前後にどう見えるかも明示する。
