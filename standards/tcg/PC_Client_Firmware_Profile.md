# TCG PC Client Platform Firmware Profile — 起動測定とイベントログ

[TCG公式原典 v1.06 rev.52](https://www.trustedcomputinggroup.org/resources/documents/pc-client-specific-platform-firmware-profile-specification)。PC ClientのUEFIファームウェアを使うVMを題材とする。ARM実機では採用するプラットフォームプロファイルを選び直す。

## 1. 起動時の処理

1. ファームウェアがTPMと選択されたPCRバンクを初期化する。
2. 信頼の根となる初期測定処理から、後続のファームウェア、UEFI設定、ブートサービス・ブートローダーなどのイベントを測定する。
3. 測定対象に応じて該当PCRへ反映し、ログにイベントメタデータとダイジェストを残す。
4. OS起動後にログを取得し、TPM QuoteのPCR情報と照合する。実行時計測のIMAログ等は別の入力として特徴を管理する。

Secure Bootでは署名・許可情報を検査して実行可否を制御する。Measured Bootではイベントを記録・集約して後で照合できるようにする。起動拒否、測定の有無、ネットワーク許可はそれぞれ別に試験する。

## 2. データ形式

| 要素 | 形式・観測 |
|---|---|
| Spec IDイベント | Crypto Agileログで後続のアルゴリズムIDとダイジェスト長を解釈する手掛かり |
| TCG_PCR_EVENT2 | PCRIndex、EventType、ダイジェスト集合、EventSize、Event |
| ダイジェスト集合 | 個数とアルゴリズムごとのダイジェスト。選択バンクと各イベントのサイズを検査 |
| Event | イベントの種類に応じた情報。表示名・パス文字列を無条件にハッシュ入力にしない |
| EV_NO_ACTION | 情報通知として処理を分けるイベント。通常の測定Extendと区別 |

代表例としてPCR 0はファームウェアの測定、PCR 4はブートコード・アプリケーション関連、PCR 7はSecure Bootポリシー関連の観察に使う。採用版のイベント定義とプラットフォーム実ログの対応を原典で確認する。イベントのバイナリ表現はログ仕様のエンディアンに従い、TPMコマンド本体のマーシャリングを安易に流用しない。

## 3. 鍵・設定・OSS対応

UEFIのPK／KEK／db／dbxはSecure Bootと更新の権限に関わる。AKはPCR状態を署名し、ファームウェア署名鍵そのものは検証器へ配布しない。OVMFコード領域と変数ストアを分け、A/B固有の可変ストアとswtpm状態を使う。ブートイメージ版、OVMF版、Secure Boot状態、署名データベース、PCRバンクをベースラインセットとして記録する。

Linuxでは `/sys/kernel/security/tpm0/binary_bios_measurements` が利用できる環境で `tpm2_eventlog` に渡して解析する。QEMU OVMFとswtpmは仮想化、tpm2-toolsは証跡の調査、Keylimeは測定ポリシー評価の候補。ログの開示を制限し、認証された管理経路で収集する。

## 4. 正常系・異常系の検証

| 条件 | 証跡と合格条件 |
|---|---|
| 承認済み設定で起動 | ログ解析、対象PCRへの再生、Quote照合が通る |
| OVMF VARS内の承認済み設定を変更 | イベント差分と対象PCRを説明できる。変更の可否は測定ポリシーで決まる |
| ログを途中で打ち切る | 長さ解析またはPCR照合で止まり、判定不能を記録 |
| Secure Bootで信頼されないイメージ | 強制モードでは起動可否のログを確認。旧起動時のPASSで認可が開かない |
| ログを取得できない | 収集経路を確認し、ログ必須の評価は保留または隔離 |

演習ではOVMF更新の前後に、どの変更を新しい期待値として承認し、どの変更を隔離するか表にする。旧版許容終了時の操作、Windows等の別プラットフォーム向けベースライン流用の危険、証跡収集に失敗した場合の保守復旧を記述する。
